Incidents

Méthode de calcul & indépendance de la mesure
  • Les sondes s'exécutent sur GitHub Actions, en dehors de l'infrastructure Zelhay. Chaque résultat est commité dans le dépôt : l'historique est horodaté par git et non modifiable a posteriori sans trace.
  • Disponibilité = sondes réussies ÷ sondes totales sur la fenêtre, par cible. La valeur globale est la moyenne des cibles.
  • Un échec est confirmé après un nouvel essai immédiat ; une panne (incident) n'est déclarée qu'après 2 échecs consécutifs. Un échec isolé est affiché comme « dégradé ».
  • Pour les adresses IP, un ICMP sans réponse est contre-vérifié par une connexion TCP sur une liste de ports usuels (443, 80, 22, …) avant d'être compté en échec.
  • Chaque incident ouvre automatiquement une Issue GitHub, fermée au retour du service, ce qui constitue le journal public.
